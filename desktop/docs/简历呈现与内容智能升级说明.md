# 简历呈现与内容智能升级说明

本轮把 OfferFlow 从「能生成一份简历」推进到「能生成一份排版专业、内容经得起推敲的简历」。
分两层交付：**呈现层（看得见）** 与 **内容智能层（写得对）**。

---

## 一、呈现层：从 1 种版式到 6 种版式 + 真 PDF 导出

### 1. 模板系统（单一数据源）

`offerflow_desktop/services/templates.py` 定义 `ResumeTemplate` 数据类，6 套版式：
`classic / compact / elegant / tech / academic / bold`。

每个模板的参数（主色、页边距、字体、标题样式、行距、姓名字号…）**同时驱动 Word 与 PDF 两条导出链路**，
不存在「Word 改了 PDF 没改」的对不齐问题。`_resolve_template()` 在未指定模板时
会按内容量自动选择 compact 或 classic。

### 2. 纯标准库 PDF 导出

`offerflow_desktop/services/pdf_exporter.py`。背景：项目运行环境既没有 Word/LibreOffice，
也装不上 reportlab / docx2pdf（沙箱内 pypi 不可达），因此**手写 PDF 生成器**：

* `core/font_subset.py` —— 解析 TrueType 的 `glyf` / `loca` / `cmap` / `head` / `hhea` / `maxp`，
  做字体子集化（18.8MB 的 `msyh.ttc` → 约 20KB），写入 `FontFile2`。
* PDF 结构：`Type0` + `CIDFontType2` + `Identity-H` 编码 + `ToUnicode` CMap，
  保证**文本可复制、可被 ATS 解析**（用 pypdf 抽查验证）。
* **两遍渲染**：第一遍记录所有绘制调用，第二遍按「实际用到的字符」做子集。
  这样代码里动态拼出来的全角冒号、顿号都不会缺字形。
* 自动撑满一页：内容溢出则缩到 0.94；留白过多则放大，但**上限 1.10**，
  避免出现 13.6pt 的正文字号（不专业）。

### 3. 所见即所得的版式预览

`ui/template_picker.py` —— 选版式对话框，右侧用 `QPdfDocument`（QtPdf）
渲染**真实的 PDF**，而不是示意图。预览所见即导出所得。

### 4. 模块排序

生成页支持每段经历/教育条目的 ↑ ↓ 调序，以及一键「按时间倒序」。

## 二、内容智能层

### 1. 语义增强的岗位匹配

`core/semantic.py` + 重写的 `services/match.py`。

**修掉的两个退化**：

| 问题 | 原实现 | 现实现 |
| --- | --- | --- |
| `partial` 分支是空壳 | `analyze_gap` 永远返回 `partial: []` | 真正的语义近似判定，带证据句 |
| 评分是线性扣分 | `100 - 缺失数×12`，JD 越长分越低 | 加权需求覆盖度 + 语义相似度 |

**语义方案**（环境无 numpy / jieba / sklearn / sentence-transformers，纯标准库实现）：

* 切词：ASCII 词元 + CJK 实词二元组（过滤虚词与招聘套话）
* 双分支相似度：
  * 两边都有 ASCII 技术词 → `0.65 × 需求侧技术词命中率 + 0.35 × 中文需求覆盖度`
  * 否则（纯中文需求）→ `中文需求覆盖度`
* 技术词命中允许词根差异（`postgresql` ~ `postgres`），但**长度 ≥ 4 且长度比 ≥ 0.6**

**阈值标定**（`PARTIAL_THRESHOLD = 0.24`）：用 24 条真实 JD 需求做标定，
不相关项（Kubernetes / Kafka / Go / Redis / Vue / CUDA / Flink…）最高只到 **0.111**，
相关项最低 0.250 → 阈值留出 **2.16 倍安全边际**，零假阳性。

**逐条判定**（三档，各带证据）：

| 判定 | 触发条件 |
| --- | --- |
| 命中 matched | 整串即技能别名（ASCII 按词边界），或需求句内的技能词**全部**在简历里 |
| 近似 partial | 需求句内技能词命中 ≥ 50%（并列出「这条要求里还缺什么」），或语义相似度 ≥ 0.24（附简历证据句） |
| 缺失 missing | 以上都不成立 |

**顺带修掉的假命中缺陷**：别名原先用子串匹配，导致 `java` 命中 `javascript`、
`go` 命中 `google`、`sql` 命中 `postgresql`。现改为 **ASCII 词边界匹配**
（`core/text_utils.py: alias_in_text`），并把 `mysql / postgresql / oracle…`
补进 `SQL` 的别名（关系型数据库都会 SQL）。

**端到端效果**：对口简历 **72 分**（命中 7 / 近似 3 / 缺失配平），
不对口简历 **0 分**、零假阳性 → 区分度 72 分。

### 2. 表达库

`core/expression_bank.py`。`resume_review` 负责**判定**问题，
表达库负责给出**改法**：

* 强动词词库，按领域分组（技术研发 / 数据算法 / 性能优化 / 协作管理 / 产品运营 / 通用）
* 弱动词 → 强动词升级表（`负责→主导`、`参与→主导`、`协助→协同推进`…）
* 指标维度提示：写「优化」但没写优化什么 → 按句子内容推荐该补时延 / 吞吐 / 覆盖率 / 数据规模
* 要点句式骨架：「通过{方法}，{动作}{对象}，{指标}从 A 提升到 B」
* `enrich()` 挑出最需要改的 3 条，产出「原句 → 建议句」
* `summary_hint()` 按已知信息填出个人总结骨架

**约束**：只改动词与结构，保留原句的技术内容，**绝不凭空编造事实**。

### 3. 发展连续性评估

`core/continuity.py`。HR 第一反应是扫时间轴，空窗/重叠/倒挂比文笔更致命：

检查项 —— 时间写反、经历缺时间、经历早于入学、空窗期、同类经历时间重叠、
分组内未按时间倒序、职责倒挂（最近一段写得比更早的还弱）。

**阈值分档避免误报**：有全职工作经历时按职场标准（7 个月），
纯学生简历放宽到 **18 个月**——校园项目本来就是一段一段做的，
按职场标准会大面积误报（实测 8 个月的正常间隔会被误判）。

排序检查也**只在分组内**比较：教育经历与项目经历在简历里是两个独立小节，
小节之间的先后不构成乱序。

## 三、顺带修掉的 4 个运行时崩溃缺陷

用 AST 做静态审计（`tests/test_static_audit.py`）发现同一类缺陷：
**用了 `LLMWorker` 却没导入**，编译/导入/构造都不报错，直到用户点按钮才 `NameError` 崩溃。

| 文件 | 崩在哪个按钮 |
| --- | --- |
| `ui/pages/match.py` | 岗位匹配 → 计算匹配度 |
| `ui/pages/interview.py` | 面试准备 → 生成面试题 |
| `ui/pages/resume_optimize.py` | 简历优化 → 开始优化 |
| `ui/pages/salary.py` | 薪资谈判 → 读简历估市场价 |

全部已修复，并把该审计固化成常驻回归测试。
